# 问题排查

常见症状、通常的原因和处理办法。安装步骤见 [setup.zh-CN.md](setup.zh-CN.md)。[English](troubleshooting.md)

## 安装与连接

| 症状 | 通常的原因 | 怎么办 |
| --- | --- | --- |
| 问自己记录里的事，Claude 凭常识回答，没有注明文件 | 项目指令里没有知识库那一行、没保存，或者对话不在这个项目里 | 打开项目，确认指令里有初始化时给你的那一行，保存，在项目里新开对话，再问「我有哪些知识库？」 |
| 明明建过库，却说「还没有设置知识库」 | 同上；或者 `kb-libraries.json` 已不在那一行写明的 Drive 文件夹里 | 先查那一行。再到该文件夹找 `kb-libraries.json`；被移走了就移回来，或说「初始化」并指明知识库文件夹，重新登记 |
| skill 没有反应，或显示为灰色 | 没开代码执行，或 skill 被关掉了 | 「设置 → Capabilities」打开 Code execution and file creation；「Customize → Skills」把三个 skill 都打开 |
| 同一个请求有两个 skill 响应 | 同一个 skill 装了中英两个版本，或 1.x 的 kb-incremental 还和 kb-ingest 并存 | 每个 skill 只留一个版本；删除 kb-incremental |
| 提示需要连接 Google Drive | 没连 Drive 连接器，或在本次对话里没启用 | 连接 Google Drive 并在对话中启用，再说一遍请求 |
| 写入或移动时报权限错误 | 连接的 Google 账号不能编辑知识库文件夹 | 改连拥有该文件夹的账号，或给这个账号编辑权限 |
| 初始化不接受这个文件夹作新库 | 文件夹不是空的，里面有 `.md` 文件 | 新库用空文件夹。已有规范的文件夹按现有库接入 |
| 初始化问这个文件夹放的是原始文件还是知识库 | 你给的文件夹看起来像资料来源 | 原始文件在原处读取，从不登记；知识库要用单独的文件夹 |

## 入库与问答

| 症状 | 通常的原因 | 怎么办 |
| --- | --- | --- |
| 文件已入库，状态卡却没变 | 快速入库先入库，状态卡要等整合时才更新 | 说「整合」，审阅提出的改动。引用尚未整合的文件时，回答会注明这一点 |
| 入库停在预览 | 每次写入前都先预览 | 回复「确认」写入，或说出要改哪里 |
| 一次入库很慢或中途停下 | 文件多，连接器调用就多 | 超过约 30 个文件时预览会建议分两次。材料分批入库，在同一对话里说「继续入库」。换了新对话会重新开始，已入库的文件会被跳过 |
| 选错了库 | 各库的范围描述有重叠 | 在请求里点明库名；把 `kb-libraries.json` 里每个库的 scope 写成意思清楚的一句话 |
| 库里出现两个同名文件 | Drive 允许同名文件；写入被打断或手工放入 | 说「归档旧版」：先预览，再把较旧的副本移入归档文件夹 |
| 库里的文件变成了 Google 文档 | 手工上传时开着 Drive 的转换功能 | `.md` 和 `.json` 关掉转换后上传（Drive 设置里关闭「转换上传的文件」）。skill 写入的文件不会被转换 |
| 回答说库里没有记录，但你入过库 | 用词不同，或文件还没真正入库 | 换用文档里的说法再问，或问「某某文档入库了吗？」查文件索引 |

## 收件箱

| 症状 | 通常的原因 | 怎么办 |
| --- | --- | --- |
| zip 被移到异常文件夹 | 有一项违反规则；旁边的说明写明了文件、行和规则 | 改好那一项后重新入库。见 [inbox.zh-CN.md](inbox.zh-CN.md) |
| 快速入库产出的 zip 全被拒收 | 快速入库会一并交付待整合清单，其文件名以下划线开头 | 用收件箱时，把库的 `_kb.json` 里 `intake.mode` 设为 `full` |
| 上传的 zip 一直没被处理 | 没装定时触发，或没开启正式执行 | 在 Apps Script 编辑器里运行 `showStatus()`，再运行 `enableAutoRun()` |

还是解决不了：提交一个 [issue](../../../issues)，写明你说了什么、得到什么回复，附上去掉文件夹 ID 的 `_kb.json`。
