# 日常使用

每件事怎么说、之后会发生什么、哪些要等你回复。skill 会按请求判断用哪个库；有不止一个库可能对得上时，在请求里点明库名（如「工作库：……」）。下面是中文口令版（`-zh`）的说法。[English](daily-use.md)

## 怎么说

| 想做的事 | 说 | 会发生什么 | 要等你吗 |
| --- | --- | --- | --- |
| 提问 | 直接问 | kb-query 先读状态卡，再读需要的文件，每条事实注明依据文件 | 不用 |
| 记一句 | 「记一下：……」 | kb-note 存成随手记，放进该库的随手记文件夹，回复文件名 | 不用 |
| 留存回答 | 「把这个回答存下来」 | 问题、回答和依据文件一起存成随手记 | 不用 |
| 整理文档入库 | 上传或指明文件，说「入库」 | 每份材料分区、命名、查重、判定版本后写入，写入后立刻可查 | 开始时有一次预览，回复「确认」 |
| 继续大批入库 | 「继续入库」「结束入库」 | 按开始时排好的计划处理下一批；只在同一个对话里有效 | 每批的预览 |
| 更新状态卡 | 「整合」 | 给上次整合以来入库的文件补关键结论，把状态卡改动编号列出，每个数值都对照出处核对 | 逐条由你决定采用与否 |
| 整理随手记 | 「整理随手记」 | 随手记按议题归并成材料入库，再把已入库的随手记移入已入库文件夹 | 先预览，移动前再回复「确认」 |
| 清理旧副本 | 「归档旧版」「清理同名文件」 | 同名的较旧副本移入归档文件夹 | 预览 |
| 检查库 | 「体检」 | 报告过期、重复、缺漏和格式问题，并抽查状态卡数值 | 不用；不改任何文件 |
| 新增一个库 | 「新建知识库」 | 三个问题，然后写好新库并登记 | 预览 |

入库时加上「完整入库」，每个文件入库时就当场更新状态卡，不用等整合。

## 一份文档的经历

```text
上传 --「入库」--> 已入库：命名、登记索引，立刻可查
                     |
                     +--「整合」--> 补关键结论，提出状态卡改动 --你同意--> 状态卡更新
                     |
同一文档的新版本 --> 沿用同一个文件名入库；旧版移入 Archive/
```

文件整合之前，状态卡可能还没反映它。回答引用这类文件时会注明，有文件在等整合时，每个对话会提醒一次。

## 建议的节奏

- 材料一来就入库，入库后立刻可查。
- 收到提醒时说「整合」，或每周一次。
- kb-note 提醒随手记攒多了时，说「整理随手记」。
- 每月说一次「体检」；体检发现同名副本时，说「归档旧版」。

任何东西都不会被删除：旧版本和运行日志都留在归档文件夹里。

和这里说的不一样时，见[问题排查](troubleshooting.zh-CN.md)。
