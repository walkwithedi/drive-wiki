# 方法论

技能为什么这样工作：下面每条规则都对应一种更宽松的做法会导致的问题，要么答案过时，要么事实丢失。具体流程写在技能里。[English](methodology.md)

## 问题

助手可以根据你的文档作答，但原始文档之间互相矛盾：旧方案、新决定、后来又改了的会议结论。提问时再去检索，返回的是最匹配的那份，而不是现行的那份。解决办法是在材料进来时就梳理一次，并把结果保存下来：由助手维护的知识库，而不是在一堆文档里临时检索。

## 四层结构

1. 原文文档：清理但不删减，一份一个文件，命名为 `<分区>_<议题>_<类型>_<短标题>.md`。
2. 汇总文件：状态卡（现在什么是对的）、变更轨迹（怎么变过来的）、待办或待决事项、术语表。大多数问题不用打开原文就能回答。
3. 实体页：每个人、机构、系统或项目一页，提到它的每份文档都链接过来。
4. 规范：库自己的规则（分区、议题、术语修正、阈值、实体）。技能管流程，规范管规则，并随库一起增长。

## 保持常青的规则

- **名称即版本**：文件名不带日期，同一文档的下一版落在同一个文件名上，上一版归档。两份不同的文档绝不能同名；拿不准就改名。这一条规则消除了大部分「哪一版是现行的」问题。
- **有证据才改，否则取保守做法**：判重复、判新版本、判事实变化，都要有原文为证。没有原文，就不改。文件内容哈希记在索引里，同一个文件换了名字再入库也能认出来。
- **改状态卡前先问三个问题**：新材料有没有这类事实；状态卡有没有这一条；两者是否不一致。三个都是「是」才改写。滚动的过程数据（每日进度、单笔消费）从不触发。
- **改写由脚本核对**：新旧状态卡逐条比对；少了的条目必须在改动清单里说明；未经本人同意，新卡不得少于旧卡的七成。
- **数值对照出处核对**：状态卡的改动交你审阅前，脚本先到依据文件里查其中的日期、长引语和具体数字；查不到的值标出来由你决定，因为换算得出的值也可能是对的。体检时对整张状态卡做同样的核对。
- **每份材料都有处置判定**：新增、更新、有争议或无新内容。有争议的不改状态卡，把两边的原文交你决定；无新内容的照常入库、可以查到，但不进改动清单。
- **不删除，不改原文**：旧版本带时间戳移入归档；发现的问题记录下来，不悄悄修正。唯一的例外是个人证件号码等敏感标识，写入前先打码。
- **不悄悄扩张**：材料放不进任何议题时，技能在最接近的分区里新增议题（绝不新增分区），重写规范并写修订说明，把改动列出来供你复核。
- **先快速入库，再整合**：把材料写进库和把它与汇总文件对齐是两个步骤。入库是机械的，逐个进行，材料一到就能查到；对齐需要精读和本人复核，所以积攒多份后分轮进行，待整合的文件记在库里的清单中。整合之前，引用这些文件的回答会注明这一点。
- **限制检索次数，固定阅读顺序**：先读状态卡，再读对应清单，再读原文，检索达到固定次数就停。关键词按库里可能的各种写法检索（原话、标准写法、旧写法、别名），一次最多合并三种。回答注明依据文件；库里没有记录的就说没有记录。
- **改什么由本人决定**：每次写入前都有预览；知识库文件夹以外的东西一概不碰。

## 随手记

值得记下的东西不都是文档。kb-note 把对话里的一句话存成知识库随手记文件夹里的一个小文件：原话、要点和背景，别的什么都不改。随手记立刻可查（回答里标注「随手记，未正式入库」），之后按分区和议题归并、批量入库，以原话为依据。标为「未确认」的随手记不会改动状态卡。

值得留存的回答（「把这个回答存下来」）也这样保存：问题和回答连同依据文件存成快照，入库为问答存档。它可以查到、带日期，但从不作为改动状态卡的依据，因为它的依据就是库本身。

## 敏感信息

知识库可以开启敏感分级（`_kb.json` 的 `sensitivity`；生活预设默认开启）。证件号、卡号、账号、密码等标识在写入或显示前打码，只留最后几位；健康和财务信息照实记录、从不解读，回答只报告记录了什么，不给建议。

## 为什么用 Google Drive 和 claude.ai

- **你自己掌握的普通文件**：知识库就是你 Drive 里的一个 Markdown 文件夹。不用技能也能读，能用 Drive 搜索，任何编辑器都能打开（借助 Google Drive 桌面版，还能作为 Obsidian 库打开）。
- **什么都不用装**：技能在 claude.ai 和 Claude 应用里运行，网页、手机都能用。脚本在 Claude 自己的沙箱里运行，只用 Python 标准库；没有 Python 时，技能手工完成同样的工作并注明。
- **注册表和库放在一起**：库的清单是 Drive 里的一个文件，只在项目指令里写一次；以后新增库只改这个文件。
- **检索只在库内进行**：每次 Drive 检索都按库文件夹 ID 限定在库内、只查一层，归档和无关文件永远不会进入回答。
- **检索看的是正文**：Drive 既查文件名也查文件内容，事实按写下它的原话就能查到，中文同样适用。
- **手机上就能入库**：记录、入库、提问都是在 Claude 应用里对话完成，不用提交、分支或终端。
- **不用 git 也有版本记录**：新版本沿用旧版的文件名，旧版移入归档文件夹；事实的变化写进变更记录。没有东西被删除。
- **数据留在你自己的 Drive**：库只存在你的 Google 账号里，谁能看由 Drive 的共享设置决定，不会进入任何代码仓库。

## 交付：直接写入或经收件箱

Drive 允许一个文件夹里有多个同名文件，所以新版本必须在旧版本移入归档之后才写入。

- **直接写入（默认）**：你确认预览后，Claude 通过 Drive 连接器逐个写入，同一步把旧版本移入归档。简单，适合大多数库。
- **zip 加收件箱**：入库结果打成一个 zip，你原样上传到库的收件箱文件夹，由 Apps Script 收件箱解压分拣、归档旧版；只要有一个条目不合规（文件名不在分区范围内、缺少属性区、含未打码的标识），整包拒收；处理结果发邮件告诉你。适合一次交付很多文件、连接器无法写入，或者想在助手和知识库之间多一道检查的情况。设置方法见 [inbox.zh-CN.md](inbox.zh-CN.md)。

## 预设提供什么

两个起点，建库时都可以修改：工作库（目标与计划、项目与任务、方案与成果、会议与决定、制度与流程、组织与职责、数据与报告、参考与模板）和生活库（健康、财务、保险、住房、家庭、证件与法律事务、设备订阅与出行、学习、参考资料）。生活预设包含敏感分级。
